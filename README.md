**Відкритий шаблон автоматичних Telegram-сповіщень про повітряні тривоги в Україні.** Поточна прикладна конфігурація стежить за **Житомирським районом** і загальнообласними тривогами на основі даних Ubilling / alerts.in.ua. Рішення можна адаптувати до інших районів та областей, які підтримує джерело даних. Код призначений для окремого проєкту Google Apps Script і **не містить реальних токенів, приватних Chat ID та ID Google Sheets**.

> **Важливо:** не покладайтеся виключно на цього бота для сповіщень про небезпеку. Дані API, розклад запуску скрипта й Telegram можуть затримуватися або бути недоступними. Користуйтеся офіційними каналами оповіщення.

## 🌍 Можна адаптувати для інших регіонів України

**Житомирський район — приклад налаштування, а не обмеження архітектури.** Цей репозиторій можна використати як основу для Telegram-каналу іншого району або області, **якщо потрібна територія та її рівні тривоги доступні у джерелі даних**.

У `src/Code.gs` потрібно налаштувати такі значення у `CONFIG`:

| Налаштування | Що змінити |
|---|---|
| `DISTRICT_UID`, `DISTRICT_NAME` | UID та назву потрібного району |
| `OBLAST_UID`, `OBLAST_NAME` | UID та назву відповідної області |
| `YELLOW_MESSAGE`, `RED_MESSAGE`, `CLEAR_MESSAGE_TITLE` | Тексти сповіщень для своєї території |
| `STATE_SCOPE_KEY` | Унікальний ключ для нової території, щоб не змішувати стани |
| `buildWeeklyStatisticsMessage()` | Текст повідомлення для тижня без тривог: у прикладі він містить назву Житомирського району |

Також налаштуйте власний Telegram-канал і Google Sheets через **Script Properties** та перевірте результат на тестовому каналі. **Не копіюйте UID з прикладу для іншої території** — звіряйте їх з актуальними даними API.

> Це **адаптований шаблон, а не готовий перемикач для будь-якого міста чи громади**. Для населених пунктів або громад, які джерело не представляє як окрему територію, може знадобитися зміна логіки визначення тривоги. Проєкт не замінює офіційне оповіщення.

## Можливості

- Перевіряє рівень загрози **кожну хвилину**: район `59` і область `10` (загальнообласна тривога також стосується району).
- Публікує лише зміни: 🟡 **жовтий**, 🔴 **червоний**, 🟢 **відбій**. Дронова небезпека відображається через жовтий рівень, **без окремого лічильника «дронова»**.
- У повідомленні про відбій показує тривалість події.
- Веде історію в Google Sheets: `Тривоги`, `Події`, `Тижневі звіти`.
- Готує тижневу статистику: кількість, загальна та найбільша тривалість, жовтий/червоний рівні; короткий формат для тижня без тривог.
- Налаштовує щопонеділкову публікацію приблизно о 08:00 за київським часом.
- Автоматично видаляє оперативні повідомлення приблизно через 24 години (очищення раз на 5 хвилин). **Тижневі звіти не видаляються**.
- Надсилає **всі Telegram-повідомлення тихо з 22:00 до 07:00** за `Europe/Kyiv` (нічні переходи на літній/зимовий час враховуються). Повідомлення **з’являються в каналі, але не створюють звукове сповіщення**; це не відкладена публікація.
- Застосовує блокування паралельних перевірок, дедуплікацію станів і повторні спроби тимчасових помилок API.

## Швидкий запуск — окремий проєкт Google Apps Script

**Не змінюйте наявний робочий проєкт.** Створіть новий Apps Script для GitHub-версії. Якщо обидві копії одночасно публікують у той самий канал, з’являться дублікати.

1. У [Google Apps Script](https://script.google.com/) створіть **новий проєкт**.
2. Відкрийте `src/Code.gs`, скопіюйте весь код в окремий файл `Code.gs` нового проєкту. Встановіть часовий пояс `Europe/Kyiv`; за потреби скористайтеся вмістом `src/appsscript.json`.
3. У Google Sheets створіть **окрему таблицю** для історії. Скопіюйте її ID з адреси `https://docs.google.com/spreadsheets/d/<ID>/edit` (не публікуйте ID у GitHub).
4. У Google Apps Script відкрийте **Project Settings → Script Properties** і додайте чотири обов'язкові значення:

   | Ключ | Значення |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | Токен від [@BotFather](https://t.me/BotFather) |
   | `TARGET_CHAT_ID` | `@your_test_channel` або числовий ID чату |
   | `CHANNEL_FOOTER` | `📲 @your_test_channel` (текст під повідомленням) |
   | `HISTORY_SPREADSHEET_ID` | ID окремої таблиці Google Sheets |

5. Додайте бота **адміністратором тестового Telegram-каналу** з дозволами на публікацію і видалення повідомлень.
6. У списку функцій Apps Script запустіть `testDistrictLevelsApi()` — перевірка джерела, **без публікації**. Далі `testHistoryConnection()` для перевірки таблиці. Дозвольте запитані доступи.
7. Запустіть `testYellowMessage()` (публікує тестове повідомлення, видаляє його приблизно через 2–5 хвилин).
8. Запустіть `setupAutomation()` — створяться тригери щохвилинної перевірки, очищення та тижневого звіту. Далі `showSystemStatus()` — перевірка стану **без виводу секретів**.

> За замовчуванням `PUBLISH_CURRENT_ON_SCOPE_CHANGE: false`: на першій синхронізації бот запам'ятовує активний стан, але не публікує його повторно. Після цього всі зміни публікуються. Для іншої поведінки змініть константу в `src/Code.gs`.

**Перш ніж підключати реальний канал**, зупиніть автоматизацію старої копії через `removeAutomation()` **тільки коли будете свідомо переносити роботу**. Під час підготовки GitHub нічого в старому проєкті змінювати не потрібно.

## Альтернатива: синхронізація через `clasp`

[Google clasp](https://developers.google.com/apps-script/guides/clasp) дозволяє оновлювати окремий Apps Script із Git-репозиторію.

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json
# Замініть REPLACE_WITH_YOUR_NEW_SCRIPT_ID на Script ID НОВОГО Apps Script
clasp push
```

Перед командою `clasp push` увімкніть **Google Apps Script API** в налаштуваннях користувача Apps Script, якщо це потрібно. **`clasp push` переписує файли цільового Apps Script**: перевіряйте, що `.clasp.json` містить ID **нового, не робочого** проєкту.

`clasp` зберігає код із `src/`; `.clasp.json` і `.clasprc.json` у Git не потрапляють.

## Публікація на GitHub

У папці `air-alerts-github`:

```bash
git init
git add .
git commit -m "Initial public-safe air alert notifier"
# Створіть порожній репозиторій на GitHub і додайте його URL:
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/air-alerts-telegram.git
git push -u origin main
```

Або якщо встановлений та авторизований [GitHub CLI](https://cli.github.com/):

```bash
gh repo create air-alerts-telegram --public --source=. --remote=origin --push
```

**Не комітьте:** Telegram-токен, ID приватного чату, ID таблиці, `.clasp.json`, `.clasprc.json`, експорти Script Properties або файли з резервними копіями, що містять секрети. Якщо токен коли-небудь потрапив у публічний Git-коміт, **перевипустіть його через BotFather**; видалення секрету тільки з нового коміту не прибирає його з історії Git.

## 🧪 Перевірка перед публікацією

Установіть Node.js і в корені репозиторію виконайте:

```bash
node --test tests/*.test.cjs
```

Тести перевіряють граничні моменти тихого режиму, пріоритет червоного рівня, район/область, надсилання Telegram з правильним прапорцем та відсутність типових hardcoded секретів. Тести **не викликають реальний API і не публікують Telegram-повідомлення**. Таку саму перевірку виконує GitHub Actions при push/PR. Автоматичний деплой свідомо **не налаштовано**.

## Безпека, обмеження й підтримка

- Значення `Script Properties` не публікуються разом із `.gs` і зберігаються **для конкретного Apps Script проєкту**. Це налаштування доступу, а не шифроване сховище: обмежуйте доступ до редактора Apps Script.
- Унікальність повідомлень забезпечується **в межах однієї інсталяції**; дві незалежні копії в одному каналі можуть дублювати одна одну.
- API може змінити формат `raw`, назви рівнів і регіональні ідентифікатори. За невідомої структури скрипт не повинен публікувати помилковий відбій.
- Google Apps Script запускає time-driven тригери **приблизно** за розкладом. Тижневий звіт виходить близько 08:00 у понеділок, а не гарантовано секунду в секунду.
- Telegram має часові обмеження на видалення повідомлень; тому застосовано 24 години з резервом і повторні спроби.
- Для зміни регіону треба змінити `DISTRICT_UID`, `DISTRICT_NAME`, `OBLAST_UID`, `OBLAST_NAME` та тексти в `CONFIG` — без сліпого копіювання UID.

Докладний перелік Script Properties, правила обслуговування та міграції: [docs/SCRIPT_PROPERTIES.md](docs/SCRIPT_PROPERTIES.md).
