# Налаштування Script Properties та безпечний запуск

## Де заповнювати

У **новому** проєкті Google Apps Script: **Project Settings → Script Properties → Add script property**. Додавайте чотири значення окремо. Не створюйте файл `secrets.gs`, не вставляйте токен у `Code.gs` і не додавайте свої реальні значення у README.

| Ключ | Обов'язково | Приклад (несправжні дані) | Призначення |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | так | `123456:REPLACE_ME` | Доступ бота до Telegram API |
| `TARGET_CHAT_ID` | так | `@your_test_channel` | Канал або чат для публікацій |
| `CHANNEL_FOOTER` | так | `📲 @your_test_channel` | Підпис у кінці повідомлень |
| `HISTORY_SPREADSHEET_ID` | так | `REPLACE_WITH_SHEET_ID` | Історія тривог і звітів |

`Script Properties` належать окремому Apps Script проєкту: нова копія **не має** автоматичного доступу до властивостей старої копії. Значення потрібно створити для нової інсталяції вручну.

## Система рівнів

- `NONE` — відбій; `YELLOW` — жовтий рівень (у цьому проєкті окремо не рахуємо «дронову» небезпеку); `RED` — червоний рівень.
- Беруться до уваги повітряні тривоги, що належать до Житомирського району `59`, або оголошені для всієї Житомирської області `10`.
- Якщо джерело повернуло інший тип чи невалідну структуру, потрібна перевірка схеми API — не можна вважати це автоматичним відбоєм.

## Тихий режим

`QUIET_HOURS_START: 22`, `QUIET_HOURS_END: 7`, `API_TIMEZONE: 'Europe/Kyiv'` задаються в `src/Code.gs`.

- 21:59 — звичайне повідомлення.
- **22:00–06:59** — `disable_notification: true`, без звуку.
- **07:00** — звичайне повідомлення.
- Тестові повідомлення завжди тихі, незалежно від часу.
- Нічна тиша не скасовує й не відкладає повідомлень; вони надходять у канал одразу.

## Функції Google Apps Script

| Функція | Що робить | Публікує в Telegram? |
|---|---|---|
| `testDistrictLevelsApi` | Перевіряє API, показує знайдені рівні | Ні |
| `testHistoryConnection` | Перевіряє доступність історії | Ні |
| `testYellowMessage` | Тестує жовтий рівень | Так, позначка **ТЕСТ** |
| `testRedMessage` | Тестує червоний рівень | Так, позначка **ТЕСТ** |
| `testClearMessageWithDuration` | Тест відбою з тривалістю | Так, позначка **ТЕСТ** |
| `testWeeklyReportPreview` | Попередній перегляд тижневої статистики | Ні |
| `checkAirAlert` | Оперативна перевірка/відправка при зміні | Так, якщо є зміна |
| `sendWeeklyStatistics` | Реальна публікація тижневого звіту | Так |
| `setupAutomation` | Установлює всі тригери | Не прямо; запускає очищення |
| `removeAutomation` | Прибирає автоматичні тригери цієї копії | Ні |
| `showSystemStatus` | Друкує тільки безпечні поля стану | Ні |
| `resetAlertState` | Обнуляє локальний стан цієї копії | Ні (але наступна перевірка сприйме запуск як новий) |

## Безпечний перенос без дублікатів

1. Ведіть налаштування нової копії на **тестовому каналі**. Перевірте всі тести та тригери.
2. Не вмикайте обидві автоматизації одночасно на одному каналі.
3. Лише коли готові до переходу, у старому проєкті вручну виконайте `removeAutomation()`; перевірте тригери в інтерфейсі Google Apps Script.
4. У Script Properties **нового** проєкту змініть `TARGET_CHAT_ID` і `CHANNEL_FOOTER` на бойові значення. Запустіть `setupAutomation()` у новому проєкті.
5. Збережіть старий проєкт окремо як резервну копію, але не запускайте в ньому тригери. Не переносіть приватні Script Properties у Git.

Для історії можна створити нову Google Sheets (без залежності від старих даних), або свідомо використати ту саму таблицю: **дві активні копії з однією історією не підтримуються**.

## Захист секретів

- `TELEGRAM_BOT_TOKEN` ніколи не логується командою `showSystemStatus()`.
- Не публікуйте скриншоти Script Properties без приховування значень.
- Якщо токен уже був у публічному Git або переданий стороннім, перевипустіть його через [BotFather](https://t.me/BotFather), потім змініть `TELEGRAM_BOT_TOKEN` у новому Apps Script.
- Не вмикайте GitHub Actions автоматичний `clasp push` без окремого налаштування GitHub Secrets і перевірки Script ID: так можна випадково переписати робочий проєкт.
