# Налаштування Script Properties та безпечний запуск

## Де заповнювати

У **новому** проєкті Google Apps Script: **Project Settings → Script Properties → Add script property**. Додавайте потрібні значення окремо. Не створюйте файл `secrets.gs`, не вставляйте токен у `Code.gs` і не додавайте свої реальні значення у README.

| Ключ | Обов'язково | Приклад (несправжні дані) | Призначення |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | так | `123456:REPLACE_ME` | Доступ бота до Telegram API |
| `TARGET_CHAT_ID` | так | `@your_test_channel` | Канал або чат для публікацій |
| `CHANNEL_FOOTER` | так | `📲 @your_test_channel` | Підпис у кінці повідомлень |
| `HISTORY_SPREADSHEET_ID` | так | `REPLACE_WITH_SHEET_ID` | Історія тривог і звітів |

`Script Properties` належать окремому Apps Script проєкту: нова копія **не має** автоматичного доступу до властивостей старої копії. Значення потрібно створити для нової інсталяції вручну.

## 🌍 Вибір регіону без редагування коду

Якщо **жодного** з регіональних ключів немає, працює демонстраційний профіль: Житомирський район (UID `59`) + Житомирська область (UID `10`). Для будь-якої іншої території задайте повний набір власних ключів. **Неповна конфігурація викличе помилку, а не візьме випадковий UID із прикладу.**

| Ключ | Режим `district` | Режим `oblast` |
|---|---|---|
| `REGION_MODE` | `district` | `oblast` |
| `DISTRICT_UID` | UID потрібного району (обов'язково) | Не задавати |
| `DISTRICT_NAME` | Назва району (обов'язково) | Не задавати |
| `OBLAST_UID` | UID області (обов'язково) | UID області (обов'язково) |
| `OBLAST_NAME` | Назва області (обов'язково) | Назва області (обов'язково) |
| `ADDITIONAL_DISTRICT_UIDS` | Не задавати | За потреби список UID районів через кому, наприклад `501,502` (вигадані ID для прикладу!) |

**Режим `district`:** враховує повітряні тривоги обраного району **та загальнообласні тривоги** відповідної області.

**Режим `oblast`:** без додаткових UID враховує **тільки події, оголошені на рівні області**, а не всі окремі районні тривоги. Щоб включити районні тривоги, задайте `ADDITIONAL_DISTRICT_UIDS` із **перевіреним повним переліком потрібних районів**. Якщо якихось UID бракує, ці районні тривоги не відобразяться. **Не слід трактувати режим `oblast` без повного переліку районів як охоплення всієї області.**

**Перевірка до запуску:**

1. Знайдіть актуальні ідентифікатори території у джерелі API/документації.
2. У Google Apps Script додайте потрібні Script Properties (без справжніх секретів у коді).
3. Запустіть **`setupRegion()`** — перевірить формат UID, запитає API й покаже поточні збіги, режим і назву території. **Не надсилатиме повідомлень**.
4. Важливо: джерело може повертати **лише активні тривоги**. Якщо збігів немає, `setupRegion()` **не може підтвердити, що UID існує**. Не сприймайте нуль збігів як успішну валідацію ID: звірте їх поза скриптом.
5. Перевірте повідомлення на тестовому Telegram-каналі. Використайте **окрему таблицю Google Sheets для кожного регіону**, щоб тижнева статистика не змішувалася між територіями.
6. Лише після перевірки виконайте `setupAutomation()`.

Зміна регіону змінює `STATE_SCOPE_KEY` автоматично: перша перевірка нової території синхронізує її поточний стан без дублювання початкового повідомлення. Попередня історія в таблиці **не очищується автоматично**.

## Система рівнів

- `NONE` — відбій; `YELLOW` — жовтий рівень (у цьому проєкті окремо не рахуємо «дронову» небезпеку); `RED` — червоний рівень.
- За замовчуванням приклад використовує Житомирський район `59` та Житомирську область `10`. Для власного регіону діє схема з попереднього розділу.
- Якщо джерело повернуло інший тип чи невалідну структуру, потрібна перевірка схеми API — не можна вважати це автоматичним відбоєм.

## Тихий режим

`QUIET_HOURS_START: 22`, `QUIET_HOURS_END: 7`, `API_TIMEZONE: 'Europe/Kyiv'` задаються в `src/Code.gs`.

- 21:59 — звичайне повідомлення.
- **22:00–06:59** — `disable_notification: true`, без звуку.
- **07:00** — звичайне повідомлення.
- Тестові повідомлення завжди тихі, незалежно від часу.
- Нічна тиша не скасовує й не відкладає повідомлень; вони надходять у канал одразу.

## Функції Google Apps Script

| Функція | Що робить | Публікує в Telegram? |
|---|---|---|
| `setupRegion` / `testRegionApi` | Перевіряє регіональні параметри й стан API (не гарантує правильність UID без активної тривоги) | Ні |
| `testDistrictLevelsApi` | Сумісний із попередніми інструкціями псевдонім тесту API | Ні |
| `testHistoryConnection` | Перевіряє доступність історії | Ні |
| `testYellowMessage` | Тестує жовтий рівень | Так, позначка **ТЕСТ** |
| `testRedMessage` | Тестує червоний рівень | Так, позначка **ТЕСТ** |
| `testClearMessageWithDuration` | Тест відбою з тривалістю | Так, позначка **ТЕСТ** |
| `testWeeklyReportPreview` | Попередній перегляд тижневої статистики | Ні |
| `checkAirAlert` | Оперативна перевірка/відправка при зміні | Так, якщо є зміна |
| `sendWeeklyStatistics` | Реальна публікація тижневого звіту | Так |
| `setupAutomation` | Установлює всі тригери | Не прямо; запускає очищення |
| `removeAutomation` | Прибирає автоматичні тригери цієї копії | Ні |
| `showSystemStatus` | Друкує тільки безпечні поля стану | Ні |
| `resetAlertState` | Обнуляє локальний стан цієї копії | Ні (але наступна перевірка сприйме запуск як новий) |

## Безпечний перенос без дублікатів

1. Ведіть налаштування нової копії на **тестовому каналі**. Налаштуйте `REGION_MODE` і відповідні UID; перевірте `setupRegion()`, інші тести й тригери.
2. Не вмикайте обидві автоматизації одночасно на одному каналі.
3. Лише коли готові до переходу, у старому проєкті вручну виконайте `removeAutomation()`; перевірте тригери в інтерфейсі Google Apps Script.
4. У Script Properties **нового** проєкту змініть `TARGET_CHAT_ID` і `CHANNEL_FOOTER` на бойові значення. Запустіть `setupAutomation()` у новому проєкті.
5. Збережіть старий проєкт окремо як резервну копію, але не запускайте в ньому тригери. Не переносіть приватні Script Properties у Git.

Для історії варто створити нову Google Sheets, особливо коли змінюєте територію, або свідомо використати ту саму таблицю: **дві активні копії з однією історією не підтримуються**.

## Захист секретів

- `TELEGRAM_BOT_TOKEN` ніколи не логується командою `showSystemStatus()`.
- Не публікуйте скриншоти Script Properties без приховування значень.
- Якщо токен уже був у публічному Git або переданий стороннім, перевипустіть його через [BotFather](https://t.me/BotFather), потім змініть `TELEGRAM_BOT_TOKEN` у новому Apps Script.
- Не вмикайте GitHub Actions автоматичний `clasp push` без окремого налаштування GitHub Secrets і перевірки Script ID: так можна випадково переписати робочий проєкт.
